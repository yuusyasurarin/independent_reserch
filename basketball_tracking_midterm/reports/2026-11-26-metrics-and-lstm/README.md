# ボール追跡とシュート判定の評価指標、LSTMの検討（2026-11-26）

ボール追跡とシュート判定のそれぞれについて評価指標を決め、録画データで測りました。あわせて、シュート判定にLSTM（時系列を扱うニューラルネット）が使えるかを小さく試しました。

## 結論

- **ボール追跡**は、TSR@0.5を主な指標にし、「リング付近のTSR」「別の物体に乗っている割合」「間引き率」などを補助に使います。バッテリー駆動の当日2モデルは、TSR@0.5が79.7〜83.2%でした。
- **シュート判定**は、「シュートを数えられたか」（再現率・適合率）と「成功・失敗が合っているか」（正解率）を分けて測ります。当日のモデル2（バッテリー駆動）の追跡結果では、27本中24本を数え、24本とも成功・失敗が正しく、全体の正解率は88.9%でした。
- **LSTMは、今のデータ量（27本）では、ルールによる判定より大きく劣りました**（成功・失敗の正解率52〜70%、ルールは数えた分なら96〜100%）。仕組みとしては使えますが、学習に使える実際のシュートを数百本単位で集める必要があります。明日の撮影は、そのデータ集めの第一歩にできます（5章）。

## 1. ボール追跡の評価指標

正解の枠があるexperiment10（2,512フレーム、ボールが見えている1,883フレーム）で測ります。正解は採点にだけ使います。スクリプトは `scripts/evaluate_tracking_suite.py` です。

| 指標 | 意味 | 何がわかるか |
|---|---|---|
| TSR@0.5（主指標） | ボールが見えているフレームのうち、出力した枠が正解の枠と半分以上重なった割合。枠を出さなかったフレームは失敗 | 追跡全体の精度 |
| TSR@0.3 | 重なりの基準を3割に下げたもの | 位置はほぼ合っているが枠の大きさがずれる場合を許す |
| 平均IoU | 正解の枠との重なり具合（0〜1）の平均 | 枠の合い方の細かさ |
| 中心のずれ（中央値・95%点） | 出力した枠の中心と正解の中心の距離（ピクセル） | 普段のずれと、大きく外れたときのずれ |
| 出力率 | ボールが見えているフレームのうち、何か枠を出した割合 | 見失いの多さ |
| 別物体率（最長） | 出力した枠が正解と全く重ならない割合と、それが続いた最長時間 | 頭や靴などへの乗り移りと、そこからの復帰の速さ |
| リング付近のTSR@0.5 | 正解の中心がリングから80px以内にあるフレームだけのTSR@0.5（experiment10では137フレーム） | シュート判定に必要な場面での精度 |
| 間引き率 | 処理が間に合わず追跡処理を省いたフレームの割合（リアルタイム実行のみ） | リアルタイムで追いつけているか |

## 2. シュート判定の評価指標

シュートは「1本ごとの出来事」なので、フレーム単位ではなくシュート単位で数えます。スクリプトは `scripts/evaluate_shots.py` です。

正解は、experiment10・11・12のリング付近の場面を切り出して目で確認した27本です（成功11本、失敗16本。[data/shot_labels_visual.csv](../../data/shot_labels_visual.csv)）。目視は1人（Claude）で、まだ本人の確認を受けていません。また、追跡がリング付近に一度も持ってこなかったシュートは、候補に入っていない可能性があります。

判定したシュートと正解のシュートは、フレームの範囲が重なれば（前後15フレームの余裕あり）同じシュートとみなし、1対1で対応づけます。

| 指標 | 計算 | 何がわかるか |
|---|---|---|
| 試投の適合率 | 正解と対応づいた判定 ÷ 判定した本数 | シュートでないものをシュートと数えていないか |
| 試投の再現率 | 判定と対応づいた正解 ÷ 正解の本数 | 実際のシュートを数え落としていないか |
| 試投のF値 | 適合率と再現率の調和平均 | 上の2つをまとめた値 |
| 成否の正解率 | 対応づいたシュートのうち、成功・失敗が合っていた割合 | 数えたシュートの成否判定の正しさ |
| 成功の適合率 | 「成功」と判定したうち、本当に成功だった割合 | 得点の数えすぎ |
| 成功の再現率 | 本当に成功したシュートのうち、「成功」と判定できた割合（数え落としも失敗扱い） | 得点の数え落とし |
| 全体の正解率 | 数えられて、かつ成否も合っていた本数 ÷ 正解の本数 | 最終的な使いやすさ |
| 得点の誤差 | 映像ごとの、判定した成功数と実際の成功数の差 | スコア表示としてのずれ |

### 結果

| 追跡の結果（軌跡） | 試投 適合率 | 試投 再現率 | 成否の正解率 | 成功 適合率 | 成功 再現率 | 全体の正解率 |
|---|---:|---:|---:|---:|---:|---:|
| 正解の軌跡（experiment10のみ、5本） | 100% | 80.0% | 100% | − | − | 80.0% |
| AC・条件G 960（判定ルールを作るときに見た軌跡） | 100% | 88.9% | 100% | 100% | 90.9% | 88.9% |
| **電池・モデル1（G 704）** | 96.0% | 88.9% | 95.8% | 90.0% | 81.8% | 85.2% |
| **電池・モデル2（G＋ROI 960）** | 100% | 88.9% | 100% | 100% | 90.9% | 88.9% |

- 下の2行は、当日と同じバッテリー駆動・同じ設定で、3本の映像を30fpsのカメラ入力として流した追跡結果に判定をかけたものです（experiment10は1章の1回目の測定、experiment11・12は今回の測定。間引き率はexperiment11で18〜24%、experiment12で7%）。
- モデル1の誤り1件は、experiment11の成功シュート（2553〜2612フレーム）でした。追跡の位置が一瞬ずれて、1本のシュートが「失敗」と「成功」の2本に分かれて数えられました。
- 数え落とし3本（どの軌跡でも共通）は、リングに届かない短いシュート、ボードの裏に外れたシュート、リング下からのレイアップ（追跡がリングより上のボールを捉えられなかった）です。
- 2行目は、判定ルールを作るときに見た軌跡そのものなので、成績がよく見えるのは当然です。参考として載せています。

## 3. LSTMは使えるか：小さな実験

### やったこと（`scripts/shot_lstm.py`）

成功か失敗かを当てる部分だけを、LSTMで試しました（シュートがどこにあるかは正解ラベルから与えます）。

- **入力**：シュート1本につき60フレーム（2秒）分のボールの位置。ボールがリングに一番近づいたフレームを真ん中にします。各フレームは「リング中心からの横のずれ」「リングの高さからの縦のずれ」（どちらもリング半径を1とした値）と「ボールが見えているか」の3つです。
- **モデル**：2層のLSTM（隠れ状態32）＋出力1つ（成功の確率）。
- **実験A（合成データで学習）**：放物線の軌道、ネットを通るときの減速、リングやボードでの跳ね返り、追跡のぶれや見失いを入れた合成の軌跡を8,000本作って学習し、実際の27本でテストしました。
- **実験B（実データだけで学習）**：3本の映像のうち2本のシュートで学習し、残り1本でテストする、を3回繰り返しました（1本抜き交差検証）。
- どちらも乱数の種を変えて5回ずつ行いました。軌跡はモデル2（バッテリー駆動）の追跡結果です。

### 結果（成功・失敗の正解率、実際の27本）

| 方法 | 5回の正解率 | 平均 |
|---|---|---:|
| 全部「失敗」と答える（基準） | − | 59.3%（16/27） |
| 実験A：合成データで学習 | 51.9%、70.4%、70.4%、70.4%、59.3% | 64.4% |
| 実験B：実データ2本で学習 | 66.7%、70.4%、66.7%、66.7%、63.0% | 66.7% |
| ルールによる判定（2章、モデル2の軌跡） | − | 88.9%（数えた24本では100%） |

- 実験Aは、合成データのテストでは96〜97%当たったのに、実際のシュートでは平均64.4%に落ちました。合成の軌跡と実際の軌跡の違い（ネットやボードでの動き、追跡のぶれ方）を学習できていないためです。成功シュート11本のうち、「成功」と答えられたのは毎回6本程度でした（[lstm_model2.json](lstm_model2.json)）。
- 実験Bは、学習に使えるのが10〜20本しかなく、全部「失敗」と答える基準をわずかに上回る程度でした。

### 判断

- **LSTMは仕組みとしては使えます**（入力の作り方と学習・評価のプログラムはできました）。ただし今の27本では、ルールによる判定のほうがずっと正確です。
- 時系列モデルが力を発揮するのは、ルールでは書きにくい場面です。例えば、リングの上を転がってから入る、リングの手前を通る（2Dでは区別しにくい）、追跡が一瞬ずれる、などです。今回のルールの誤りや数え落としも、まさにこの種類でした。
- そのためには、実際のシュートを少なくとも数百本（成功・失敗それぞれ100本以上が目安）集めて、正解を付ける必要があります。1回の練習試合で20〜40本のシュートが撮れるとすると、10回分程度です。

## 4. LSTMを使うための進め方（提案）

1. **データを集める**：明日から、追跡時に `--record-raw` で生映像を残し、シュートの成否を紙やスマホに記録します。
2. **ラベル付けを楽にする**：ルールによる判定が出した候補（時刻と成否）を下書きにして、人は確認と修正だけをします。数え落としを拾うため、リング付近を通った場面も一覧にします。
3. **役割を分ける**：シュートの候補を見つけるのはルール（今のもの）に任せ、LSTMは候補ごとの成功・失敗の判定に使います。少ないデータでも学習しやすくなります。
4. **データを増やす工夫**：左右反転、合成データでの事前学習＋実データでの調整。
5. **評価**：映像単位で分けて（学習に使った映像ではテストしない）、2章と同じ指標でルールと比べます。

## 5. 限界

- 正解ラベル（27本）は、Claudeが1人で目視して付けたもので、本人の確認がまだです。
- 追跡の評価はexperiment10の1本だけで、ほとんどの条件が1回の測定です。同じ設定でも2.4ポイント程度ぶれます。
- シュート判定の評価は3本の映像の27本だけです。experiment12は判定ルールを作るときにも使いました。
