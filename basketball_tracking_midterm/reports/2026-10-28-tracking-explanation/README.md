# 実動画で見るKCFとLKの成功・失敗

experiment10の実画像と、2026-10-28の修正済みE・Gの記録を使った説明です。画像はローカルの `results/tracking_explanation_20261028/` に保存しています。成功・失敗を理解しやすい場面を事後に選んだ例であり、方式の成功率を測り直したものではありません。

| 方法 | 成功例 | 失敗例 |
|---|---|---|
| KCF | フレーム564→565、18.800→18.833秒。実際のKCF枠がボールに追従 | フレーム420→421、14.000→14.033秒。修正済みKCFは失敗を返す |
| LK | フレーム424→425、14.133→14.167秒。28点中25点が有効、LK枠を採用 | フレーム420→421、14.000→14.033秒。30点中1点のみ有効、LKを棄却して再検出判断へ |

## KCFの画像

[KCFの成功・失敗画像](../../results/tracking_explanation_20261028/kcf_success_failure.png)

左列が前画像、中央が次画像、右列が説明用に計算した相関フィルタの応答マップです。緑枠は正解、オレンジ枠は実際のOpenCV KCF出力、ピンクの点線枠は説明用フィルタの最大応答位置です。

KCFは前画像の対象と周辺からフィルタを学習し、次画像の各ずれに対する応答を計算します。成功例では、応答の山がボールの移動位置に対応します。説明用フィルタは右4px・下1pxを選び、実際のKCFもボールを追えています。

失敗例では、ボールが左へ大きく移動しています。初期枠中心から次画像の正解中心まで約52pxあり、説明用フィルタの横方向探索範囲を越えます。そのため別の位置が最大になっています。実際の修正済みOpenCV KCFはこのフレームで失敗を返し、枠を出していません。「最大の応答が存在する」ことと「追跡に成功した」ことは同じではありません。

**右列はOpenCVの内部応答を取り出したものではありません。** OpenCVのPython APIから内部応答が取得できないため、輝度1チャンネル・Gaussian kernelの説明用KCFを別途計算しています。Eで使うOpenCVの特徴構成や閾値とは異なります。応答値0.739や0.200は確率ではなく、これらだけから実際のOpenCVの失敗判定理由を断定できません。図の探索範囲も説明用モデルの範囲です。

説明用計算は、窓関数を掛けた輝度特徴、循環ずれのGaussian kernel、正解中心を山にしたGaussian目標応答、周波数領域の正則化回帰から構成しています。実装の参考は [KCFcppの著者実装](https://github.com/joaofaro/KCFcpp/blob/master/src/kcftracker.cpp)、実際のKCFの初期化・更新処理は [OpenCV 4.10.0のソース](https://github.com/opencv/opencv_contrib/blob/4.10.0/modules/tracking/src/trackerKCF.cpp)です。

## LKの画像

[LKの成功・失敗画像](../../results/tracking_explanation_20261028/lk_success_failure.png)

左列は前画像の特徴点、中央は次画像で見つかった対応点への矢印、右列は往復追跡誤差です。青は有効点、赤は除外点、緑枠は正解、オレンジ枠は採用したLK出力です。

LKは小さな画像領域の明るさの変化を使い、特徴点がどこへ動いたかを推定します。本実装では「前→次」と追跡した後、「次→前」へ戻し、元の点からのずれを調べます。往復誤差1.5px以下、OpenCVの状態フラグ、画像範囲、点同士の移動の整合性を確認します。最終的に4点以上かつ元の点数の半数以上が必要です。往復誤差が小さいだけで正しい物体上の点と保証されるわけではありません。

成功例では25/28点がまとまって左に動き、ボールの移動を追えています。失敗例では対応点が大きく散り、29/30点が除外されます。これは誤った位置をそのまま表示する例ではなく、追跡を信用できないと判断して棄却できた例です。ボール以外の背景や輪郭から抽出される点もあり、「特徴点＝ボール上の点」ではありません。

LKの点座標・状態・往復結果は、実際の `AdaptiveBallPolicy` が呼ぶ `cv2.calcOpticalFlowPyrLK` から取得しました。先頭1,100フレームを保存済みYOLO候補から再実行し、各フレームの検出判断、枠、出力元、イベントが保存記録と一致することを確認しています。正解アノテーションは例の選択と説明だけに使っています。

## 再生成

プロジェクト直下のPowerShellで実行します。元動画、正解、`results/comparison_fixed_lag_20261028/` のs/Eとs/Gの実行ログ、およびWindowsのMeiryoフォントが必要です。YOLOの再推論は行いません。

```powershell
.\.venv\Scripts\python.exe scripts/visualize_tracking_examples.py
```

出力は2枚のPNG、選択フレーム・点座標・判定を記録した `examples.json`、説明用KCFの応答配列2個です。[今回の数値記録](examples.json)も保存しています。元動画を含む画像と配列はローカル保存とし、生成コードと説明・数値記録をGitで管理します。

説明用相関マップは、既知の左右・上下移動と移動なしの合成画像で最大応答の位置を確認しました。KCF初期化・逆追跡の回帰テストを含む全42件が成功しています。詳細は [テスト記録](../../data/verification_tests.txt) にあります。
